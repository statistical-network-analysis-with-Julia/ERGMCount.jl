# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ERGMCount.jl is a Julia package for fitting Exponential Random Graph Models (ERGMs) to count-valued (integer-weighted) networks. It is a port of the R `ergm.count` package from the StatNet collection. Estimation is by maximum pseudo-likelihood only; `ergm.count`'s Monte-Carlo MLE is a disclosed limitation (`method=:mcmle` throws an explanatory `ArgumentError`; see README "Not implemented").

## Development Commands

- **Run tests:** `julia --project=. -e 'using Pkg; Pkg.test()'`
- **Load package locally:** `julia --project=.` then `using ERGMCount`
- **Build docs:** `julia --project=docs docs/make.jl` (strict: `warnonly=false`, `checkdocs=:exports` — every export needs a docstring and a `@docs` entry)
- **Benchmarks and regression gates:** `julia --project=benchmark -e 'using Pkg; Pkg.instantiate()'` once (the environment resolves from the committed `benchmark/Project.toml`, whose `[sources]` point at `..`, `../../ERGM.jl` and `../../Networks.jl`), then `julia --project=benchmark benchmark/benchmarks.jl` (BenchmarkTools suite, `BENCHJL` lines for the site's `tools/run_benchmarks.jl`, `SCALING` assertion) and `julia --project=benchmark benchmark/regression_tests.jl` (the allocation and scaling pins; CI runs it on the ubuntu/`1` cell). `benchmark/fixtures.jl` is shared by both.
- **Dev install:** `using Pkg; Pkg.develop(path=".")`

## Architecture

The entire package lives in a single file: `src/ERGMCount.jl`. It is organized into five sections:

1. **Reference Measures** -- Abstract type `AbstractReferenceMeasure` with concrete subtypes (`PoissonReference`, `GeometricReference`, `BinomialReference`, `DiscUnifReference`, `DiscUnif2Reference`). Each implements `log_reference(ref, y)`, `sample_reference(ref)`, and `_support(ref, max_val)`; `is_truncating(ref)` says whether `0:max_val` truncates it (Poisson/geometric) or is the model's own bound. Following `ergm.count`/Krivitsky (2012), `GeometricReference` is the counting measure h(y)=1 (no parameter) and `BinomialReference(trials)` is h(y)=C(trials,y) (no probability parameter) — the shape/probability is absorbed into the estimated `SumTerm` coefficient.

2. **Count-Specific Terms** -- Subtypes of `AbstractERGMTerm` (`import ERGM: name, compute, is_dyad_dependent, requires_directed`). Every term implements `name(t)`, `compute(t, net)`, and `change_stat_count(t, net, weights, i, j, old, new)` — the change in the statistic when dyad (i,j) moves from count `old` to `new`, holding other dyads fixed (implementations must not read the dyad's own current value). Both hot paths consume the change statistics as a **support profile**, `change_stats_support!(dest, term, net, weights, i, j, old, support)` (declared `public`): the fallback calls `change_stat_count` per value, and the strength terms (`_strength_profile!`: the strength excluding the dyad once, then `(s+y)² − (s+old)²`) and the triadic terms (`_tri_register!`/`_tri_integrate!`: the third-vertex minima `c_k` collected once over the neighbour intersections, then `Σ_k [min(y, c_k) − min(old, c_k)]` assembled for every `y` from a difference array in one pass) specialise it to O(degree + |support|) instead of O(degree × |support|). Every specialisation is held equal to the per-value definition by the testset "Support profiles equal the per-value change statistics"; `change_stat_count` stays the definition and stays brute-force-tested. Terms, labelled with the string R prints for the same term: dyad-independent `SumTerm` (`sum`), `NonzeroTerm` (`nonzero`), `GreaterthannTerm(k)` (`greaterthan.k`), `CountAtleastnTerm(k)` (`atleast.k`), `SmallerthanTerm(k)` (`smallerthan.k`, zero dyads counted), `EqualToTerm(v; tolerance)` (`equalto.v.pm.t`), `InIntervalTerm(a, b; open)` (`ininterval(a,b)` with R's bracket convention, `±Inf` bounds allowed); dyad-dependent `CountMutualTerm(form=:min; threshold)` (R's valued `mutual`: `mutual.min`/`mutual.nabsdiff`/`mutual.geom.mean`/`mutual.product`/`mutual.<t>`, one `_mutual_pair(t, a, b)` behind `compute` and `change_stat_count`), **Negative counts** (`_admits_negative`, `_refuse_negative_network`, `_validate_negative_terms`): on a network with a negative dyad weight (only `DiscUnif2Reference(a < 0, b)` admits one) `ergm` refuses `transitiveweights`/`cyclicalweights` ("Term may not be used with networks with negative dyad weights") and its `mutual(form="geometric")` is NaN, so `TransitiveWeightsTerm`, `CyclicalWeightsTerm` and `CountMutualTerm(:geometric)` are refused with R's sentence at `compute` (the summary statistic, as in R), at model construction and at `simulate_count_ergm` over a support reaching below 0 — never a number R does not produce (the `best = 0` floor of the two-path search would have defined one). `TransitiveWeightsTerm`/`CyclicalWeightsTerm` (R's `transitiveweights`/`cyclicalweights` with the default `(min, max, min)` triple: `Σ min(y_ij, max_k min(y_ik, y_kj))` over ordered pairs directed, unordered pairs undirected, where cyclical = transitive; `_best_twopath`/`_best_cycle_twopath(net, weights, i, j, skip)` find the strongest two-path leaving a named third vertex out, so the affected pairs `(i,l)`, `l ∈ out(j)`, and `(k,j)`, `k ∈ in(i)` — for the cycle `(a,i)`, `a ∈ out(j)`, and `(j,b)`, `b ∈ in(i)` — re-assemble their strength with the changing dyad at any value), `TransitiveTiesTerm`/`CyclicalTiesTerm` (**no R counterpart**: triple-wise minimum sums kept from 0.1, names `transitiveties.count`/`cyclicalties.count`, not validated against R), `NodeOSumTerm`, `NodeISumTerm`, `NodeSumTerm` (squared strengths; no R counterpart either — `ergm`'s `nodecovar` family is a covariance). `CountMutualTerm` (every form), `CyclicalTiesTerm`, `NodeOSumTerm`, `NodeISumTerm` declare `requires_directed = true`: `compute` returns 0 on an undirected network, and `CountERGMModel`/`simulate_count_ergm` **refuse** them there with a hint (`NodeSumTerm`, or drop the term) rather than fit an identically-zero column. Coefficient labels come from the two-argument shared generic `name(term, net)`. The weights terms' profiles are sums of clamp ramps (`_ramp_register!`: `clamp(y, a, b) − clamp(old, a, b)` into the same difference array as `_tri_register!`), one two-path search per affected pair rather than one per pair and support value.

3. **Model** -- `CountERGMModel{T,D,TT<:Tuple,R}` mirrors `ERGM.ERGMModel{T,D}`: `network::Network{T,D}`, `terms::TT` (a **Tuple**, so the support profiles fold statically through the `@generated` `_accumulate_conditional!` (the conditional's linear predictor) and `_fill_slab!` (a design slab) — never `map` over the tuple, which boxes from 32 terms on; both pinned at 0 B for a 36-term tuple), `reference::R`; no `directed` field, `is_directed(model)` reads `D`; `show` prints the one-line summary `ERGM.ERGMModel` prints. Constructed from a Tuple, a Vector or a single term. The inner constructor is where the data are **validated**, so `count_mple(model)` and the bootstrap refits inherit every refusal: a two-mode network (`_refuse_two_mode`, ERGM.jl's reasoning — the within-mode dyads would be enumerated as observed zeros; `BipartiteNetwork` methods on the constructor, `fit_ergm_count` and `simulate_count_ergm` give the same message instead of a MethodError), a directed-only term on an undirected network (`_validate_count_terms`), and the counts themselves (`_validate_count_weights`: edges but no `:weight` attribute at all is refused — it would fit as a 0/1 network on which `sum ≡ nonzero` — and so is an edge without `:weight` among weighted ones, naming the first bare edge and how many (a bare edge is a data gap, never a count of 1; R's `response=` never reads a missing value as 1); every value must be an `Integer` or integer-valued `Real`; a negative value only under `DiscUnif2Reference`; the validator returns the smallest count so `_validate_negative_terms` can refuse the terms R refuses on negative data). A binary ERGM.jl term (`ERGM.Edges()`, `ERGM.Mutual()`, …) is refused by `_validate_count_terms` (`_is_count_term`: has a `change_stat_count` method) naming its count analogue (`_count_analogue`), instead of a `MethodError` in the design build; `simulate_count_ergm(terms, net, coefs)` with the arguments swapped is the same named `ArgumentError` as `fit_ergm_count(terms, net)`. `fit_ergm_count(net, terms; weight=:w)` is R's `response="w"`: `_with_weight` fits a `copy` carrying the counts under `:weight`. `has_dyad_dependent(::CountERGMModel)` is a method of the ONE `ERGM.has_dyad_dependent` predicate (never a same-named private); it decides `is_exact`, the `show` caveat and `approximations`.

4. **Estimation** -- `fit_ergm_count` (aliases `ergm_count`, `fit_count_ergm`) builds the model and calls `count_mple`, a proper count MPLE that enumerates each dyad's full conditional P(y_ij=y|rest) ∝ h(y)·exp(θ'Δg(y)) over the support — the reference measure enters the estimator directly — and maximizes it with the shared `Networks.newton_fit` (`ERGM.newton_fit` is the same binding). `loglik` is the maximized pseudo-log-likelihood; the result answers the full StatsAPI surface (`coef stderror vcov confint loglikelihood nobs dof aic bic coeftable`; `aic`/`bic` are pseudo-likelihood criteria; `coeftable` is the `Networks.CoefficientTable` that `show` prints, from the same `z_values`/`p_values`).

   **Compressed design** (`_count_design`): dyads with identical (terms × support) change-statistic slabs share one row with a per-support-value observation count `C[s, r]` and a weight `n_tot[r]` — every dyad of a dyad-independent model is ONE row whatever the network size; the per-dyad build sweep writes into a reused buffer and copies only a new slab (O(unique slabs) allocation, pinned). `_count_derivatives(design, cols, mask)` is the `(ll, grad, hess)` closure over that design with workspaces allocated once (≤ 512 B per evaluation, pinned). `_row_logZ!` is the ONE conditional computation shared by the derivatives, the boundary-mass and the omitted-tail diagnostics.

   **Boundary statistics** (`_count_boundary!`): a statistic at its smallest/largest attainable value on every dyad's conditional support has no finite MPLE. As in R `ergm`, its coefficient is fixed at ∓Inf (SE 0, p 0, excluded from `dof`), each dyad's support is restricted to the values that statistic allows (`mask`), the detection is iterated to a fixed point, and `_warn_count_boundary` says so. `se=:bootstrap`, `simulate_count_ergm` and `gof` refuse a fit with a fixed coefficient.

   **Continuation in the support** (`_support_ladder`/`_ladder_fit`): Newton from θ = 0 on a wide support overshoots (the counting measure's initial conditional is uniform on `0:max_val`), so every fit climbs `0:base`, `0:2·base`, ..., the requested top, each rung warm-started from the one below (`θ0=`); bounded references with a wide support climb it too, and bootstrap refits start at θ̂. When Newton cannot move from a start (singular Hessian at a point-mass conditional, e.g. `BinomialReference(100)`), `_coordinate_ascent_start` (bisection on each coordinate's monotone score) supplies a rescue start; `newton_fit` runs under a `NullLogger` (`_quiet_newton`); `count_mple` itself reports a singular or ill-conditioned final Hessian once (see **Conditioning** below).

   **Error-controlled support** (panel item 17, N6): with `max_val=nothing`, `_adaptive_support_fit` fits at `max(10, 2·max count)`, refits at twice the bound, and stops when **all** of `max|Δθ| ≤ support_tol·SE` (default 1e-3; absolute scale where the SE is NaN/0), the expected number of dyads past the previous bound (`_omitted_tail`) ≤ `support_tol`, and the boundary mass at the new top ≤ `BOUNDARY_MASS_TOL` hold; the larger-bound fit is reported. `support_control ∈ (:bounded, :fixed, :converged, :unconverged)`, `support_stable::Bool` (false only for `:unconverged`) plus `support_delta`/`omitted_tail` (0.0 for a bounded reference, NaN for a fixed `max_val`) record what happened; `:unconverged` (cap `max_doublings=8`) is warned — naming the achieved δ, the final `max_val` and the improper-family explanation — listed in `approximations` and printed. The doubling also **stops at the first rung that is not usable** (`_support_rung_usable`: `converged` and `hessian_cond ≤ _HESSIAN_COND_TOL`), returning `:unconverged` with `support_delta = omitted_tail = NaN`: a collinear design (`sum + greaterthan(2) + atleast(3)`) used to run all 8 doublings, growing the design 2^8×, and then be misdiagnosed as "not normalisable"; now the non-convergence/separation/conditioning warnings carry the diagnosis alone (`count_mple` prints a one-line "stopped at max_val = … because the fit there did not converge" instead), `show`'s support line says "adaptive doubling stopped here", and the "not normalisable" sentence is reserved for a doubling that genuinely exhausted `max_doublings`. Bounded references never loop. The old fixed default was 1.4e-6/3.9e-6 from the exact MLE on `zach`, above the fixture's tolerance; the default path is now pinned against the fixture directly. **The fit is not bit-identical to 0.1.x** (the compressed design changes the summation order); the fixture tolerance (1e-6, reproduced to ~1e-12) is the standard.

   **Convergence** is loud: a final fit that exhausts `maxiter` or cannot move is warned about (naming `maxiter`, `tol` and the pseudo-score norm, with the two ways out), recorded as `converged=false` with `iterations`/`gradient_norm`, listed in `approximations`, printed by `show`, and never `is_exact` — nor is a fit with a `±Inf` coefficient. The coordinate-ascent rescue is tried only when Newton stopped *before* its budget; running out of `maxiter` is the caller's budget and is reported as such. `warn=false` silences every fit diagnostic (boundary, truncation, non-convergence, separation, conditioning) without changing the record; the bootstrap refits use it and report exclusions once, in aggregate.

   **Separation** (`_count_separated`, the count analogue of `ERGM._separated`): a design on which the pseudo-likelihood is flat along a *combination* of the statistics — `sum + nonzero` when every count is 0 or 1 (`sum − nonzero` at its minimum on every dyad), `sum + atleast(2)` when every count is 0 or 2 — has no finite MPLE, and `_count_boundary!` (one column at a time) cannot see it; Newton "converges" in one step to θ ≈ (−21, 21) with SE 2e4. After a converged Newton, two signatures must BOTH hold for the fit to be declared separated: (1) some row has a masked support value at which no dyad of the row was observed whose exponential tilt θ'Δg is more than 18.42 nats below the row's largest tilt (the reference measure is left out of that gap, since a wide Poisson support is improbable under `h` whatever θ is), and (2) the next Newton step `−H⁻¹g` exceeds `1e-3·max(‖θ‖, 1)` or the Hessian is not invertible. Either alone is benign (a wide truncated support under a strongly negative `sum` fires (1); zach's fixture model has step 3e-12 and condition number 54). A separated fit is `converged=false, separated=true`, warned with R's "The MPLE does not exist!" sentence (`_warn_count_separated`), listed in `approximations`, printed by `show`, never `is_exact`, and excluded by the bootstrap (an unconverged replicate). The adaptive support loop needs no special case: on the asymptote δ is tiny in SE units and the tails vanish, so it stops at the first doubling; the verdict is what matters.

   **Conditioning** (`_hessian_cond`, `_collinear_names`): `hessian_cond` is the 2-norm condition number of the negative pseudo-Hessian over the free coefficients (1 when none is free, `Inf` when singular or non-finite). Above `_HESSIAN_COND_TOL = 1e8` the fit warns (unless separated, whose caveat subsumes it), naming the statistics whose loadings on the smallest-eigenvalue eigenvector exceed 30% of the largest (`collinear`, e.g. `greaterthan.2` and `atleast.3` — the same statistic on integer counts — or `sum` and `nonzero` on a 0/1 network); `show` prints the caveat under `Converged:` and `approximations` lists it. An exactly singular Hessian (`newton_fit` breaks with `converged=false` and NaN SEs) is reported in the same sentence.

   **Standard errors** (`se_type`, reported by `Networks.se_method`): `se=:hessian` (default) is the inverse negative pseudo-Hessian — anticonservative for any dyad-dependent model. `se=:bootstrap` is a parametric bootstrap on the ONE shared `Networks.bootstrap_cov` loop (same API as `ERGM.mple`: `n_boot`/`boot_burnin`/`boot_interval`/`rng`); replicates without a finite, converged MPLE are returned as NaN, **excluded** from the covariance with a warning, and kept in `boot_replicates`. The `se=` keyword is validated by the shared `Networks.check_se`. The point estimates are identical under both; when a bootstrap was used `show` prints no caveat at all and `approximations` drops the anticonservatism sentence, keeping only the point-estimate caveat.

5. **Simulation** -- `simulate_count_ergm` is a **Gibbs sweep** (`_gibbs_sweep!`): every dyad is redrawn once per sweep from its full conditional by the per-dyad kernel `_gibbs_update_dyad!(rng, current, weights, terms, θ, i, j, support, log_h, η, buf)`: `_dyad_conditional!` writes `η[s] = exp(η_s − max η)` with `η_s = log h(y_s) + θ'Δg(old → y_s)` accumulated from the support profiles (`_accumulate_conditional!`, static over the tuple) and returns their sum; `_draw_index(rng, η, total)` is an inverse-CDF draw on those **un-normalised** weights (one `rand`, one pass, no normalising pass); `_set_dyad!` touches the network only when the value actually changes, and an edge exists for every **non-zero** count (`y != 0`, not `y > 0`): under `DiscUnif2Reference(a < 0, b)` a negative draw is stored as a negative `:weight` and read back by `dyad_value` — round 1 collapsed such draws to 0, so the sampler drew from a different law than the (correct) estimator fit. `gof`'s count-value panel runs over `lo:hi`, every value the observed or a simulated network takes (`_dyad_value_extrema`, `_dyad_value_counts(net, lo, hi)`). Every diagnostic number in `show`, `approximations` and the warnings is formatted by `_fmt3` (`@sprintf "%.3g"`; `round(x, sigdigits=3)` printed `6.969999999999999e-32`), so the docs' quoted outputs are what a user gets. It is *not* a Metropolis toggle chain, so `ERGM.mh_toggle!` deliberately does not apply. `burnin`/`interval` are **sweeps** and default through `_gibbs_defaults(n_dyads)`, the shared `ERGM._mcmc_defaults` rule converted from toggles to sweeps (`cld(20·n_dyads, n_dyads)` = 20 burn-in sweeps, `cld(max(100, n_dyads ÷ 10), n_dyads)` = 1 between draws beyond ten nodes); `gof` and the bootstrap's `boot_burnin`/`boot_interval` resolve through the same function, and the explicit-specification form keeps a literal `max_val=20`. The chain state is `copy(net0)` and every retained draw `copy(current)` — `Base.copy(::Network)` is the ONE copier (graph and attribute dicts duplicated, vertex attributes preserved, no `deepcopy`). The loop snapshots `:weight` once into the typed `Dict{Tuple{T,T},Int}` (`get_edge_attribute(net, :weight, Int)`) and maintains it incrementally, **zeroing rather than deleting** an entry when an edge is removed (`dyad_value` reads it behind `has_edge`, and never deleting keeps the Dict from rehashing on remove/re-add cycles). Masked networks and non-finite coefficients are refused (`require_observed(...; face_ok=false)`); `gof` (a method of `Networks.gof`) inherits both.

## Missing-data contract

No routine exposes a `missing=` keyword: the count MPLE would enumerate an unobserved dyad as an observed row and the Gibbs sweep would condition on a face value nobody observed. `fit_ergm_count`, `count_mple` and `simulate_count_ergm` call `require_observed(net; face_ok=false)` and declare `Networks.missing_policies(f) = (:error,)`; the refusal names `clear_missing_dyads!` and never `:face`. `missing_method(fit) == :rejected`. Two-mode networks are refused on the same principle (`_refuse_two_mode`, at the model constructor and in `_simulate_count`): a within-mode dyad is not a dyad, and enumerating it as an observed zero would be a number computed from data nobody observed.

## Hot paths and their pins

Three loops carry every cost in the package, and each is pinned by `@allocated` in `test/runtests.jl` and again, standalone, by `benchmark/regression_tests.jl`:

- **The Gibbs dyad update** (`_gibbs_update_dyad!`): the conditional and the draw are 0 B for every term in `ALL_TERMS`, directed and undirected, and so is every update that does not *insert an edge* — unchanged, changed on an existing edge, removed — measured as the worst over every dyad of a warmed chain (two sweeps at a dense specification give both weight dictionaries every key they will need, then sweeps at the target coefficients). An insertion is the one mutation that can allocate: Base's `_growat!` reallocates Graphs' sorted adjacency vector on a first-half `insert!` once its front slack is used up — a few hundred bytes amortised over many insertions, independent of the model, measured 0–35 B per insertion and pinned at ≤ 128 B per insertion (+1 KiB) over ten sweeps at 12 and 40 nodes (test) and five at 34 and 100 (gates). A sweep in which no value changes is 0 B without any warm-up, and the benchmark suite's `sweep/n34`, `sweep/n100` medians are 0 allocations. Time: ≈ 0.3–0.6 µs per dyad for `sum + nonzero + mutual.min + nodeOSum` (the committed 0.2.0-dev baseline was 3,108 B and 3.7 µs).
- **The MPLE design build** (`_count_design_rows!`/`_fill_slab!`): 0 B per dyad; the sweep allocates only for new slabs, so a dyad-independent model costs the same bytes at 12 and at 40 nodes (one row) and a dyad-dependent one is proportional to its distinct slabs, never to the dyads.
- **The derivative closure** (`_count_derivatives`): ≤ 512 B per `(ll, grad, hess)` evaluation whatever the rows and support (192 B measured).
- **Scaling**: with the mean degree held fixed, a sweep at n = 100 must cost at most 2× more *per dyad* than at n = 34 (`benchmark/benchmarks.jl` `SCALING` line and the gates' last testset; 0.8× measured) — the profiles are O(degree), so the sweep is O(dyads).
- **Static folds**: `_accumulate_conditional!` and `_fill_slab!` are 0 B for a 36-term tuple (above Base's 32-element `map` limit).

`benchmark/benchmarks.jl` also times `fit/zach_default` (the fixture model on the error-controlled path, ≈ 0.29 ms, 26 KiB), `fit/zach_maxval60` (≈ 1.0 ms, 56 KiB), `derivatives/zach` and `sweep/n34`, `sweep/n100`, and prints the `BENCHJL` lines `tools/run_benchmarks.jl` in the site repo consumes.

A `PrecompileTools` workload at the end of the module (two 6-node networks, both directednesses, the Poisson default path, a bounded reference with a dyad-dependent term, `show`/`coeftable`/`confint`, `simulate_count_ergm`, `gof`, and a guarded two-replicate bootstrap under a devnull logger) takes the first `fit_ergm_count` in a fresh session from ≈ 2.2 s to ≈ 0.01 s and the first `gof` from ≈ 0.5 s to ≈ 0.01 s (package precompile 2 s → 8 s).

## Golden fixtures (statnet ergm / ergm.count)

Two fixtures, both generated by checked-in R scripts and loaded with Networks.jl's `load_golden` (which throws without `[provenance]`):

- **`test/fixtures/count_terms.toml`** (`test/fixtures/r/count_terms.R`, ergm 4.12.0 / ergm.count 4.1.3): **term parity**. The summary statistics *and the coefficient names* R prints for `sum`, `nonzero`, `greaterthan(2)`, `greaterthan(4)`, `atleast(3)`, `transitiveweights(min,max,min)`, `cyclicalweights(min,max,min)`, `smallerthan(2)`, `equalto(3)`, `ininterval(1,3)` (all four bracket forms), `mutual(form=min/nabsdiff/geometric/product)`, and `greaterthan(-1)`/`atleast(0)` (thresholds at or below 0 count the zero dyads: 561 on zach), on `zach` (undirected, frozen as a valued edge list) and on a seeded 8-actor directed count matrix (frozen as an edge list), at 1e-9 — deterministic functions of the graph, so any disagreement is a term-formula bug; plus a 3-actor network with a **0-valued tie** (`set.edge.value` on an existing tie, frozen with the zero in its edge list), on which R's `nonzero` is 1 and the threshold terms count the tie with the empty dyads — `compute` reads `dyad_value`, never `ne(net)`, so it agrees. The testset rebuilds all three networks from the TOML alone, compares `[name(t, net) ...]` to R's names exactly and `compute` row by row. `mutual(form="threshold")` is deliberately **not** pinned: ergm 4.12.0's own `summary()` fails at C model initialisation, the script freezes that error (`r_error_mutual_threshold`) and stops if it ever starts working (so the row gets added), and `CountMutualTerm(:threshold)` is tested by hand value. There is no estimation in this fixture (ergm.count has no MPLE; an MCMLE row on a dyad-dependent model would be a Monte-Carlo blur on both sides).
- **`test/fixtures/zach_poisson.toml`** (`test/fixtures/r/zach_poisson.R`): the **exact-MLE** fixture. Model: `zach ~ sum + nonzero`, `reference = ~Poisson`, on ergm.count's bundled Zachary karate-club network (counts 0-7).

`sum + nonzero` is **dyad-independent on purpose**: each dyad is then an independent draw from a two-parameter law with an **exact MLE**, and `count_mple`'s dyad-conditional enumeration *is* the likelihood — so ERGMCount.jl computes that exact MLE and is held to **1e-6**, not to "within Monte-Carlo error". It reproduces it to ~2e-12, both at the pinned `max_val=30` and on the **default path** (adaptive doubling 14 → 28); the testset also shows that the old fixed default (14) misses the tolerance, so the doubling is what earns it.

Two things the fixture had to get right, and both are worth knowing:

- **The golden value is solved analytically**, not with `optim`. The score equations collapse to one monotone scalar root-find. `optim(BFGS, reltol=1e-14)` — the obvious way — landed **7e-6** from the true optimum, *above* the tolerance it was meant to police. A reference number only good to 7e-6 cannot hold anyone to 1e-6. The frozen residual score is ~1e-14.
- **Truncation is measured, not assumed.** The Poisson reference is unbounded; the estimator enumerates `0:max_val` and the exact MLE truncates nothing, so they estimate the same thing only if the boundary mass is negligible. The fixture freezes `P(y > 30) = 6.9e-23` under the fitted law against a smallest-used conditional probability of 2.3e-3 — nineteen orders of magnitude — and the testset re-asserts ERGMCount.jl's own reported `boundary_mass` against that bound, so a future `max_val` that started to bite goes **red** rather than quietly widening the gap.

`ergm.count`'s own fit is MCMLE (statnet has no valued MPLE) and sits **0.0103** from the exact MLE — *further* than ERGMCount.jl does. It is frozen as a cross-check on R, not as the reference standard.

## Key Dependencies

- **Networks.jl** -- the `Network{T,D}` type and edge weights (`get_edge_attribute(net, :weight, Int)`); the shared contracts imported by name: `newton_fit`, `z_pvalues`, `check_se`, `CoefficientTable`/`coeftable`, `bootstrap_cov`, `require_observed`/`missing_policies`, `gof`/`GOFResult`, the result-metadata protocol (`estimand`, `objective`, `is_exact`, `se_method`, `missing_method`, `approximations`)
- **ERGM.jl** -- `AbstractERGMTerm`, the statistic protocol (`name`, `compute`), the traits `is_dyad_dependent`/`requires_directed`, the predicate `has_dyad_dependent`, and `ERGM._mcmc_defaults` (public) for the sampler defaults
- **Distributions.jl** -- reference-measure draws in `sample_reference` and `quantile(Normal())` for `confint`
- **Statistics** (stdlib) -- `cov` over the surviving bootstrap replicates
- **Logging** (stdlib) -- `NullLogger` around the shared Newton kernel (see continuation above)
- **PrecompileTools** -- the `@compile_workload` at the end of the module (see "Hot paths and their pins")

StatsBase is no longer a dependency.

## Conventions

- All term structs subtype `AbstractERGMTerm` and must implement `name()`, `compute()` and `change_stat_count()`; declare `is_dyad_dependent(::T) = false` only when the change statistic depends on nothing but `old`/`new`, and `requires_directed(::T) = true` when the statistic is identically zero on an undirected network.
- Edge weights are stored as the `:weight` edge attribute on `Network` objects; absent weight means binary (0/1).
- `fit_ergm_count` is the standardized entry point (ecosystem `fit_<model>` naming); `ergm_count` is the R-faithful alias and `fit_count_ergm` a legacy alias — all the same function (`const`). Keyword vocabulary: `maxiter`, `n_sim`, `rng`, `n_boot`.
- All randomness flows through `rng::AbstractRNG` keywords (default `Random.default_rng()`); never call bare `rand()`.
- Julia >= 1.12 is required (see `[compat]` in Project.toml).
- Tests in `test/runtests.jl` include brute-force verification of every `change_stat_count` (`ALL_TERMS` holds every term, every `mutual` form and every `ininterval` bracket form, so a new term goes there and is then brute-force-, profile- and 0-B-tested for free), the R-parity term testset (hand values, R labels, the `SmallerthanTerm` boundary case), the term-parity golden fixture, hand-computed term values, Poisson-rate recovery of the MPLE, estimation↔simulation round trips, the boundary-statistic limits in closed form (zero-truncated Poisson, restricted binomial), the support profiles against the per-value change statistics for every term, both directednesses and every support value, `@allocated` pins on the design sweep, the derivative closure, the Gibbs dyad update and a whole sweep (0 B on a grown chain at two sizes), the sweep-count pin of the dyad-scaled defaults (a default-path draw equals the spelled-out 20/1 one and differs from a 19-sweep one; `gof` and the bootstrap inherit it), `Networks.check_statsapi(fit; strict=true)` on three fits, a fresh-process thread-count-independence check of the bootstrap, loud non-convergence (`maxiter=1` on a single-rung support), and the golden fixture on both the pinned and the default support path (plus its unstable-support twin).
